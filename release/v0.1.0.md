# ValueRoute v0.1.0 — Automatic controller selection with independent role certification

ValueRoute answers whether a multi-agent task should stay on the host controller or be split across workers, and how many. v0.1.0 adds automatic controller selection: in `automatic` orchestration mode the service picks the first certified controller from versioned model profiles and keeps it sticky, with a safe expected-version-protected switch that commits atomically. Controller and Worker roles are now certified independently in the model manifest, so no single aggregate ranking is used.

## What changed

- Automatic controller selection (FR-201): `OrchestrationMode.automatic`; `ensure_controller` picks the first certified controller from candidate profiles and stays sticky across calls and journal replay.
- Safe controller switch (FR-202): refuses while session tasks are running, requires the current expected version, releases the previous epoch, and commits the new epoch and session in one journal frame.
- Independent role certification (FR-203): `model-manifest.schema.json` gains `controller_status` alongside `worker_status`; a deterministic `ControllerRanker` selects only certified, compatible controllers and never a single aggregate ranking.
- New API surface `POST /v1/controller-sessions/{session_id}/epochs/automatic` and `/epochs/switch`, both Idempotency-Key protected; versioned request schemas added and checked against OpenAPI.
- Read-only advisory routing (v0.0.2): boundary classification, requirement profiler, candidate suggestions with cost/latency estimates, and durable shadow records.
- Offline evaluation set with three frozen task families and live A/B/C measurements; 36-item design acceptance checklist verified.
- Simplified-Chinese README (README.zh-CN.md) alongside the English one.

## Known limitations

- Automatic controller selection picks the host controller only; it does not auto-delegate worker tasks.
- Worker delegation stays disabled until the offline evaluation set demonstrates quality, cost, or latency gains.
- A `controller_status` of `certified` requires reproducible measurement evidence; until then the status must stay `candidate`, so automatic selection may find no eligible controller.
- Evaluation acceptance is keyword-based, not full task execution; quality_claim is false and no model-quality certification is implied.
- Production authentication and remote deployment hardening are outside this local-first release evidence.
